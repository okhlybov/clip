Wrapping parse in a helper silently discards every option assignment. The upvar 2 mechanism writes into whatever frame calls parse (clip-0.tm:226). Verified: proc w {argv defs} { ::clip::parse $argv $defs }; w {-v} ...  the caller's variable is never created, with no error or warning. The code's own comment (clip-0.tm:224-225) admits this. A parser whose most natural usage pattern (proc main {}  helper) silently loses all options is fragile. Returning a slotvalue dict (or accepting an array name) would be composable and testable; the upvar magic is the weakest part of the design.
